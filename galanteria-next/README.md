# Galanteria Group — Next.js

The Galanteria Group site, ported from Vite + React Router + SCSS to Next.js
(App Router) + Tailwind CSS v4. Same content, same palette, same Supabase
backend; different rendering model and no stylesheets of its own.

## Running it

```bash
npm install
cp .env.example .env.local   # then fill in the two Supabase values
npm run dev                  # http://localhost:3000
```

`npm run build` produces the production build, `npm start` serves it.

## How it is put together

```
app/
  layout.js            document, fonts, language context
  (site)/              every public route — wears the header and footer
    page.js              homepage
    Aboutus/  Contact/  Projects/
    category/[slug]/  product/[slug]/  project/[slug]/
  admin/               the panel, outside the site chrome
  sitemap.js  robots.js  not-found.js
components/            one folder per area; UI primitives in components/ui
lib/
  queries.js           every read the public site performs
  supabase/server.js   the server client (cached, used by pages)
  supabase/client.js   the browser client (admin, search, forms)
i18n/ui.js             interface strings (sq/en/de)
lang.js                marketing copy (sq/en/de)
supabase/migrations/   the schema and its Row Level Security policies
```

### Rendering

Public pages are **server components**. They read Supabase during the render, so
a category page arrives with its products already in the HTML and every route
carries its own `<title>`, description, canonical URL, social tags and JSON-LD.
In the Vite build all of that was written by an effect after React mounted,
which meant anything that does not execute JavaScript saw one generic shell for
all seventeen routes.

Pages are static and revalidate every five minutes
(`REVALIDATE_SECONDS` in `lib/supabase/server.js`). Saving in the admin panel
calls the `revalidateSite` server action, so an edit shows up immediately
rather than at the end of that window.

Interactive pieces — the navbar, the slideshows, the lightbox, search, the
forms and the whole admin panel — are client components. They receive their
data as props from the server wherever there is data to receive: the category
list is read once in `components/SiteChrome.jsx` and handed to both the header
menu and the footer.

### Styling

There are no `.scss` files. `app/globals.css` holds the design tokens as a
Tailwind `@theme` — the same palette, type ladder and rhythm that used to live
in `src/index.css` — plus the base layer and the few global selectors Swiper
needs for markup it renders itself. Everything else is utilities in the markup.

Token names changed only where the old ones would have produced awkward
utilities (`--color-bg` would have meant writing `bg-bg`); the values did not.
Repeated shapes are React components (`components/ui/Button.jsx`,
`components/ui/Section.jsx`) or exported class strings
(`components/admin/ui.js`), not global classes.

Fonts are self-hosted by `next/font`. The Vite build requested the same two
families from `fonts.googleapis.com` in `index.css` *and* in three component
stylesheets.

### Language

The visitor's choice of Albanian, English or German lives in `localStorage`, so
the first paint is English and the stored choice applies on mount. Moving it to
a cookie would let the server render the right language immediately, at the cost
of opting every page out of static rendering — see the note in
`components/providers/LanguageProvider.jsx`.

## What is not here

`AdminMigrate` — the one-time import of the old hardcoded `src/data/products.js`
dataset into Supabase — was not ported. Its own documentation says to delete it
and the dataset once the catalogue is in Supabase, which it is, and carrying it
over would have meant bringing 43 MB of legacy product photography into
`public/`. The Vite project still contains it if it is ever needed again.

## Deploying

Set `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` in the host's
environment. Nothing else is required: `vercel.json`'s SPA rewrite is gone with
the SPA, `public/sitemap.xml` is generated by `app/sitemap.js` on demand, and
`npm run sitemap` no longer exists — the sitemap can no longer be older than the
catalogue.

The ten legacy category URLs (`/OfficeChairs`, `/MeetingTable`, …) are permanent
redirects in `next.config.mjs` rather than the client-side `<Navigate>` they
were before.
